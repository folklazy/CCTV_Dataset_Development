# ตรวจความพร้อมภาพด้วยสคริปต์และการตรวจระหว่าง annotation

สถานะ: **ผู้ใช้รับแนวทางลดงานตรวจซ้ำแล้ว / เครื่องมือพร้อมใช้ / ยังไม่รับรอง GT**

## ใช้ผ่านเว็บและซิงค์ข้อมูลในระบบ local

เว็บทำงานแบบ **browser → SSH tunnel → server ของผู้ใช้ → SQLite ชุดเดียว** ภาพและผลตรวจอยู่ใน private work root ของ server ไม่ต้องอัปโหลดเข้าเว็บสาธารณะ ไม่มีบริการ cloud และไม่มีการคัดลอกฐานข้อมูลแยกลงแต่ละเครื่อง

- เปิดหน้าตรวจผ่าน `localhost` บนคอมผู้ใช้ได้ โดยใช้ SSH tunnel ด้านล่าง ทุกหน้าต่างเชื่อมฐานข้อมูลชุดเดียว
- หน้าเว็บตรวจการเปลี่ยนแปลงทุก5วินาที ส่งเฉพาะผลตรวจที่เปลี่ยนผ่าน `/api/sync` ไม่โหลดภาพ2,200ภาพใหม่ทุกรอบ
- **การซิงค์ไม่ใช่ autosave:** กดบันทึกจึงส่งการแก้ไขเข้าserver เมื่อบันทึกสำเร็จหน้าต่างอื่นจะแสดงผลใหม่ ถ้าอีกหน้าต่างกำลังแก้ภาพเดียวกันจะเก็บร่างไว้และเตือน ไม่แทนข้อความที่ยังไม่บันทึก
- การบันทึกต้องส่ง `base_revision` ที่เปิดแก้มา SQLite ตรวจ revision ใน write transaction ถ้าฐานข้อมูลมี revisionใหม่จะตอบHTTP409 และไม่เขียนทับ ผู้ใช้เลือกโหลดผลล่าสุดแล้วตรวจเทียบก่อนบันทึกใหม่ ประวัติทุกรุ่นคงอยู่
- ถ้าสายSSH/เครือข่ายหลุด หน้าเว็บแสดงว่ายังซิงค์ไม่ได้ ร่างยังอยู่เฉพาะหน้าต่างที่เปิดอยู่และ **ยังไม่ถูกบันทึก** ไม่รองรับ offline synchronization queue และไม่ควรปิด/refreshขณะมีร่างที่ยังไม่บันทึก
- ข้อมูลที่กดบันทึกแล้วคงอยู่เมื่อrefreshหรือรีสตาร์ตviewer ส่วนการเปิดviewerใหม่จะได้access tokenใหม่ ต้องใช้URLส่วนตัวล่าสุด

การตรวจซิงค์ใช้สองbrowser sessionsกับภาพสังเคราะห์: บันทึกจากAแล้วBเห็นผลใหม่, Bที่มีร่างไม่ถูกทับ, stale saveถูกปฏิเสธ409, โหลดล่าสุดและบันทึกrevisionถัดไปได้, refreshและviewerrestartยังมีข้อมูล, จำลองตัด/ต่อเครือข่ายแล้วแสดงสถานะตามจริง ทั้งหมดแยกจากภาพจริงและไม่เพิ่มยอดGT

ระบบนี้เป็นเว็บlocalที่ต้องเชื่อมserverจึงอ่านภาพและบันทึกได้ **ยังไม่ใช่ชุดที่ย้ายไปทำงานofflineบนWindowsทั้งชุด** และยังไม่ซิงค์polygonกับX-AnyLabelingอัตโนมัติ

เอกสารนี้เป็นทางเข้าของ workflow ที่ผู้ใช้เลือกเมื่อ 5 พฤศจิกายน 2026 แทนการให้ Codex เปิดภาพทั้งชุดแล้วเขียนทุกช่องก่อนเริ่ม annotation เป้าหมายยังเป็น Hair / Face / Upper / Lower และสีเสื้อผ้าบน–ล่าง ชุดปัจจุบันมี 2,200 ภาพ การรับไฟล์ดู [intake revision2](../reports/SELECTED_2200_INTAKE_REVIEW_TH.md#revision2-intake) และสถานะรอบนี้ดู [รายงานล่าสุด](../reports/README.md#assisted-coverage)

## สิ่งที่เปลี่ยนและสิ่งที่ต้องตรวจจริง

1. ใช้หลักฐาน intake เดิมที่ผูกกับ source version ถูกต้อง ไม่เริ่มตรวจ export ทั้งชุดใหม่
2. สคริปต์วัดสถิติภาพและจัดคิวให้ตรวจเพิ่ม โดยไม่ใช้ detector/parser หรือส่งภาพออกไปยังบริการอื่น
3. ก่อน pilot ตรวจความหลากหลายเบื้องต้นและกรณีจำเป็นต่อการปิดกฎ ไม่อ้างว่าประเมิน semantic coverage ทุกภาพเสร็จแล้ว
4. ผู้ใช้ยืนยัน coverage รายละเอียดขณะตรวจ annotation แต่ละภาพ ไม่ต้องเขียนคำอธิบายละเอียดชุดเดิมล่วงหน้าอีกรอบ Codex ช่วยกรณีกำกวมหรือหลักฐานขัดกัน
5. ก่อนออกรุ่น ทุกภาพต้องมี coverage ที่ประเมินแล้ว พร้อมการตรวจ mask/owner/สีตามคู่มือและ receipt ของผู้ใช้ สคริปต์นี้ไม่รับรอง GT ให้

การอนุมัติ workflow นี้ไม่เริ่ม pilot/SAM3/model inference อัตโนมัติ ก่อน pilot ยังต้องปิดกติกาที่กระทบ mask และตรวจ lossless annotation bridge ตามเดิม ขอบเขต pilot24 และ release แรก300 ยังเป็นงานถัดไป ไม่ใช่ผลงานรอบนี้

## ตัวเลขที่วัดได้กับสิ่งที่ยังไม่ทราบ

| รายการ | ที่มาและวิธีใช้ | สิ่งที่ห้ามสรุปแทน |
| --- | --- | --- |
| Population/hash/geometry | ใช้ manifest และ ledger ที่รับตรวจแล้ว จากนั้นเทียบ SHA256 ระหว่างอ่านภาพเพื่อวัดสถิติ | ผ่านไฟล์ไม่เท่ากับ annotation ถูก |
| กล้องและช่วงเวลา | นับ metadata โดยคงข้อความต้นฉบับ | เวลาไม่ยืนยันแสง/IR และชื่อกล้องไม่ยืนยัน viewpoint |
| ค่าเฉลี่ย/ส่วนเบี่ยงเบนความเข้ม | Pillow L บนภาพย่อด้านยาวไม่เกิน256 ใช้ BILINEAR | ไม่ยืนยันความพร้อมของทุกส่วนร่างกาย |
| สัดส่วนพิกเซลมืด/สว่าง | ความเข้มไม่เกิน32 / ไม่น้อยกว่า224 เป็นค่าบรรยายของวิธีวัดนี้ | ไม่ใช่เกณฑ์คุณภาพสากลหรือกฎคัดทิ้ง |
| ความเข้มของขอบภาพ | FIND_EDGES ค่าเฉลี่ยภายในที่ตัดขอบหนึ่งพิกเซล | ไม่ใช่ตัวตรวจ blur ที่รับรองแล้ว; ตัวหนังสือ/พื้นหลังอาจคมกว่าคน |
| คิวตรวจเพิ่ม | edge signal กลุ่มล่าง10% ของภาพที่วัดแล้ว หรือมีมืด/สว่างอย่างน้อยครึ่งภาพ | ไม่ตัดภาพ ไม่เปลี่ยนสมาชิก ไม่เติมว่า observed/absent และไม่ยืนยันว่าเคสนอกคิวไม่มีปัญหา |
| 10 axes และ4 targets | บันทึกสิ่งที่ผู้ตรวจประกาศจากภาพที่เปิด พร้อมเหตุผล | ไม่ใช่ผลอัตโนมัติ ไม่ใช่ mask GT หรือ inter-annotator agreement |

ค่า32/224/10%/ครึ่งภาพเป็นนิยามการวัดและการเรียงคิวเท่านั้น ไม่ได้ calibrate เป็น detector สำหรับ dataset นี้ รายงาน coverage เชิงความหมายต้องแยกจากสถิติเหล่านี้ อ่านภาพต้นฉบับเมื่อคนเล็กหรือภาพย่อไม่พอตัดสิน ห้ามคัดเฉพาะภาพง่ายหรือถือว่าภาพที่ไม่มี flag ตรวจผ่านแล้ว

## ใช้งาน

โค้ด: [assisted_coverage.py](../scripts/assisted_coverage.py) และ [หน้าเว็บ](../scripts/assisted_coverage.html) ใช้ Python3.10+ และ Pillow ที่มีอยู่แล้ว ไม่ติดตั้งแพ็กเกจหรือแก้ environment อัตโนมัติ ไม่มีส่วนเรียกโมเดล/GPU

รันจาก repo นี้ โดย `$DATASET_PYTHON` ชี้ interpreter ที่มี Pillow และ `$DATASET_RUN` ชี้ private run จริงตาม handoff ห้ามใส่ข้อมูลจริงใน public config:

```bash
"$DATASET_PYTHON" scripts/assisted_coverage.py status --run "$DATASET_RUN"
"$DATASET_PYTHON" scripts/assisted_coverage.py serve --run "$DATASET_RUN" --port 8041
```

สำหรับชุดใหม่เท่านั้น: `init --binding <private SCIENTIFIC_INPUT_BINDING.json> --output <fresh external run>` แล้ว `analyze --run <run>` อย่าสร้างซ้ำหากมี run ปัจจุบันอยู่แล้ว หากหยุดระหว่างวัดสถิติ ให้ตรวจ process/lock/log ก่อนใช้ `analyze` ต่อ ผลที่ commit ใน SQLite แล้วใช้ต่อได้ ไม่เขียนทับ การพบ failure จะหยุดรอบนั้น และไม่ retry แถวที่ failed อัตโนมัติ ต้องตรวจหลักฐานและจัด revision ก่อนแก้กรณีผิดพลาด

ถ้าเปิดจากคอมอีกเครื่อง ใช้ SSH tunnel จาก **คอมของผู้ใช้**:

```powershell
ssh -N -L 127.0.0.1:8041:127.0.0.1:8041 YOUR_USER@YOUR_SERVER
```

เปิด URL ที่อยู่ใน `SERVER_PRIVATE.json` ของ run ซึ่งมี access token อยู่ท้าย URL ถ้าเลือก local port อื่น ให้เปลี่ยนเฉพาะ port ด้าน browser ให้ตรงกับ tunnel ไม่เผยแพร่ URL/token นี้บน Git ตัว server bind เฉพาะ loopback; ทุก data API ต้องมี token ไม่เปิดภาพเป็น public static URL ไม่มีบริการ cloud เพิ่ม

### ขั้นตอนในหน้าเว็บ

1. เลือกภาพจากคิวหรือค้นรหัสภาพ คลิกภาพเพื่อสลับพอดีจอกับพิกเซลต้นฉบับ
2. ตรวจภาพเต็มและคนที่ขอบภาพ รวมคนที่ detector อาจหาไม่เจอ หน้านี้ไม่ได้ใช้ YOLO เป็นตัวกำหนดว่ามีคนหรือไม่
3. กรอกชื่อผู้ตรวจ แล้วประเมิน10 axes และ Hair/Face/Upper/Lower แยกกัน แต่ละช่องเลือก เห็นหลักฐาน / ไม่แน่ใจ / มองเห็นไม่พอ / ยังไม่ได้ประเมิน พร้อม note บอกสิ่งที่เห็นหรือตำแหน่ง
4. ช่องที่ยังไม่ตรวจเก็บเป็น `not_assessed` ได้ แต่ไม่นับว่าครบ ยอมรับ `uncertain`/`unobservable` เป็นการประเมินข้อจำกัด ไม่แปลงเป็น absent หรือพร้อมทำGT
5. ยืนยันว่าเปิดดูแล้ว กดบันทึก ระบบเก็บ revision ใหม่และไปภาพถัดไป เปิดใหม่หรือ refresh แล้วรายการยังอยู่

การโหลดภาพผ่าน API เป็นเพียงหลักฐานส่งภาพถึง browser ต้องมีการยืนยันและบันทึกของผู้ตรวจแยกกัน ไม่ถือว่า render/เปิด URL เท่ากับมีคนตรวจจริง หน้าเว็บนี้เก็บ coverage แยกจาก X-AnyLabeling: สามารถใช้ประกอบการตรวจ annotation แต่ **ยังไม่มีการนำเข้า annotation อัตโนมัติหรือ lossless bridge ที่รับรองจากเครื่องมือนี้**

## หลักฐานและความปลอดภัย

- ทุก run มี CONFIG, source/UI hashes, input bindings, SQLite, STATUS และ summary ส่วนตัว แยกจาก native benchmark และฐาน coverage เก่า
- ไม่ยกยอดข้อสังเกตจาก snapshot เก่าโดย candidate ID เพียงอย่างเดียว ภาพที่ bytes เปลี่ยนต้องมี observation รุ่นใหม่ หลักฐานเก่าใช้ต่อได้เมื่อ identity/คำถาม/evidence สอดคล้องกัน
- Source path ต้องอยู่ใน image root และไม่ผ่าน symlink; อ่านอย่างเดียว ไม่มีการเขียนภาพต้นฉบับ รายชื่อจริง/metadata/ภาพ/DB อยู่ภายนอก Git
- ระหว่างวัดสถิติอ่านทีละภาพ มี committed rows ต่อภาพ; ตรวจ SHA ของ bytes ที่อ่านในรอบเดียวกัน ไม่แยกทำ full integrity scan อีกรอบ
- เปลี่ยนโค้ด/UI/control bindings แล้วไม่ฝืนใช้ fingerprint เดิม ต้องสร้าง child/revision พร้อมเหตุผล หากเปลี่ยนเฉพาะ UI อาจ reuse measurements ที่มี measurement/source bindings เท่าเดิม โดยมี explicit reuse receipt
- ไม่มี automatic model retries, inference, pseudo-label masks, annotation acceptance, training หรือ split assignment ในคำสั่งนี้

## การตรวจรับเครื่องมือและข้อจำกัด

Fixtures ใช้ภาพดำ/ขาวที่รู้ค่าพิกเซลล่วงหน้า ทดสอบค่าที่คำนวณได้ การใช้ต่อโดยไม่เขียนทับ การหยุดเมื่อ source/control เปลี่ยน การปฏิเสธ symlink/traversal และการไม่รับผลตรวจเมื่อยังไม่เปิดภาพ รวมทั้งการเก็บ revision และไม่เพิ่มยอด GT จาก coverage ดู [tests](../tests/test_assisted_coverage.py)

Browser acceptance ใช้ภาพสังเคราะห์ ตรวจโหลดภาพ กรอก14รายการ บันทึก และ refresh หลักฐานอยู่ private แยกจากผลตรวจจริง ไม่ใช้ข้อมูลสังเคราะห์เติม coverage ของชุด2,200 ภาพ การทดสอบนี้ไม่รับรองว่าผู้ตรวจจะกรอกถูกทุกภาพ และยังไม่มีผลวัดว่าลดเวลา annotation ได้กี่เท่า

**งานถัดไป:** ตรวจเคสจำเป็นต่อกติกาและปิด lossless bridge readiness → pilot24 ตามขอบเขตเดิม → ยืนยัน coverage พร้อมตรวจ annotation เป็น batches → QA และรับรองรุ่น เมื่อถึงขั้นนั้นต้องตรวจทุกภาพตามงานที่ต้องรับรอง ไม่ใช้สถิติแทน GT
